# PM Simulator - AI開発ガイドライン & ルール

本ドキュメントは、Google Antigravity が本リポジトリで作業する際に遵守すべき開発ルールとコンテキストを定義します。

---

## 🎯 プロジェクトの文脈
* **ゲーム概要**: プレイヤーが責任感を持って動き、ステークホルダーやチームをマネジメントする「プロジェクトマネージャー体験シミュレーションゲーム」
* **開発アプローチ**:
  1. **仕様化**: `docs/` 以下で、ゲームのコンセプトや仕様を文書化する。
  2. **プロトタイピング**: `prototype/` 内の Python CLI 版で、ゲームバランスとジレンマの面白さ、簡単な動作確認を行う。
     * ※ 迅速な原理確認のため、1 の「仕様化」と 2 の「プロトタイピング」は並行して進めてもよい。
  3. **本格開発**: 仕様やロジックが固まり合意が取れたら、Godot 4 (GDScript) による本格的な開発・UI実装に移行する。

## 🛠 AI支援開発の原則

### 1. 議論と仕様化の優先
* 実装に入る前に、必ずユーザーと議論を重ねて仕様を徐々に具体化・明文化すること。
* 大きな変更や新機能の追加時は、まず実装計画（Implementation Plan）を提示してユーザーの承認を得るプロセスを徹底すること。

### 2. ドキュメントの整合性
* 仕様に関する合意が得られたら、実装前に `docs/game_design.md` を必ず最新の状態に更新すること。コードと仕様書の間に乖離を作らないこと。

### 3. 技術的ルール
* **コード記述時のコア要件 (実装時必須)**:
  * **Python (プロトタイプ)**:
    * エントリポイントで標準出力をUTF-8に再設定（`sys.stdout.reconfigure(encoding='utf-8')` など）すること。
    * オブジェクト指向の明確な責務分け（データモデルとゲームエンジン）を意識すること。
  * **JavaScript (Webプロトタイプ)**:
    * コード変更時は `npm test` (Vitest) および `npm run lint` (ESLint) を実行し、ユニットテストの通過およびエラー・警告がないことを確認すること。
  * ※ PR発行前の詳細な品質検証項目・チェック手順については `.agents/skills/code-review/SKILL.md` を参照すること。

### 4. Git・ドキュメント駆動PR ＆ ブランチ管理ルール
* **共通運用規約**: Git / GitHub 操作の全共通ルールおよび詳細ガイドラインは [docs/development/git_workflow.md](file:///e:/work/pm-simulator/docs/development/git_workflow.md) を参照・厳守すること。
* **【AI必須ルール】議論確定からPR発行までの一連作業自動完遂 (End-to-End Auto PR)**:
  * ユーザーからの相談・議論を経て修正内容や実装計画が確定し、**作業を開始した後は、ファイル修正・テスト検証から `/create-pr` による PR 発行までを途中で止めず、一連の作業として自動で完遂すること。**
  * 実装完了後に「PRを発行しますか？」などの手動確認を挟まず、作業承認を得た時点で PR 発行までをシームレスに一括実行すること。
* **【AI必須ガードレール】ファイル変更着手前のブランチ自動検証**:
  * ユーザーからコード修正・テキスト変更・仕様変更リクエストを受けた際、**ファイルを1文字でも編集する前に、必ず最初のツール実行として `git branch --show-current` を確認すること。**
  * 現在のブランチが `main` の場合は、**作業を開始する前に、直ちに専用ブランチ（`feature/xxx-MMDD-HHMM`, `fix/xxx-MMDD-HHMM`, `docs/xxx-MMDD-HHMM`）を新規作成・切り替えてから作業を開始すること。**
* **自動化スキルの実行要件**:
  * **PR作成時**: ユーザーから「PR作成」「PR提出」等の依頼を受けた場合、または上記の通り議論確定後の作業完了時、必ず `create-pr` スキルのワークフローを実行すること。
  * **マージ後クリーンアップ**: ユーザーから `/clean-merged-branches`, `/clean-branches`, `/merged`, 「マージ完了」等の連絡を受けた場合、必ず `clean-merged-branches` スキルのワークフローを実行すること。

## 📂 フォルダ構成のルール
* ドキュメントは `docs/` 配下に格納する。
* プロトタイプは `prototype/` 配下に格納する。
* カスタムスキルは `.agents/skills/<skill_name>/SKILL.md` に定義する。
* Godot関連のスクリプトは将来的に `scenes/` または `src/` 配下に構造化して配置する。
