# Document Review Skill

本スキルは、PRを発行する前にドキュメント（Markdownファイル）の整合性、表記揺れ、リンク切れ、仕様書フォーマットを自動チェックするためのガイドラインです。

## 🔍 チェック項目

### 1. ドキュメント間の整合性 (AGENTS.md)
* **ゲームデザインの整合性**:
  * 変更された内容が [docs/spec/overview.md](../../../docs/spec/overview.md) や [README.md](../../../README.md) の全体方針（カフェ新規開店、3AP制、店長PM/チーフPL責務分離、コアループ等）と矛盾していないか。
* **関連ファイルの更新漏れ**:
  * 仕様書が更新・新設された場合、必要に応じて [docs/README.md](../../../docs/README.md) や関連する仕様書間のリンクが更新されているか。

### 2. 文章の品質 ＆ 表記ルール
* **誤字脱字・表記揺れ**:
  * 用語（「店長（PM）」「チーフ料理長（PL）」「動線レイアウト」「調理レシピ」「保健所」等）が表記揺れなく統一されているか。
* **Markdown フォーマット**:
  * 見出しレベル（`#`, `##`, `###`）の階層が正しく崩れていないか。
  * リストやテーブルのマークダウン文法が正常か。

### 3. リンク切れ ＆ 相対パス検証
* **ポータブルな相対パスの徹底**:
  * `file:///` や `C:/`, `/Users/` 等のローカル環境依存の絶対パスが**絶対に混入していないか**。
  * すべてのリンクがリポジトリ内の有効な相対パスになっているか。

### 4. 仕様書メタデータ ＆ ファイル分割チェック (AGENTS.md準拠)
* **YAML フロントマターの検証**:
  * `docs/spec/` 配下の仕様書ファイルに、適切な YAML フロントマター（`title`, `category`, `status`, `description`, `related_docs`）が記載されているか。
* **ファイル肥大化防止（適切な粒度）**:
  * 1つのファイルに過剰な仕様が集中しすぎていないか（目安: 100〜300行程度）。必要に応じて別仕様書（`pm_commands.md`, `events.md`, `balance.md` 等）に分割されているか。

## 🛠 実行手順
1. `git diff` で差分のある Markdown ファイル（`.md`）を特定する。
2. 上記のチェック項目に基づき、内容の一貫性・リンク・YAMLフロントマターを検証する。
3. 修正が必要な場合はPR発行前にドキュメントを更新する。
